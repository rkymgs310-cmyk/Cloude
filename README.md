# ガジェット比較ラボ

AI/ガジェット系のニッチサイトです。記事は「非共有の下書き作成 → 人の確認 → 明示的な公開承認」の順で進めます。
GitHubリポジトリは公開のため、未確認の記事はブランチ・PR・Actionsログ・Artifactsにも保存しません。

> **AI/coding agentへ**: 共通運用規約は [`AGENTS.md`](AGENTS.md)、現在のブロッカー・自動化の状態・次にやるべきことは
> [`docs/AI_CONTEXT.md`](docs/AI_CONTEXT.md) にまとめてあります。作業前に必ず確認してください。

## 構成

- **Astro** — 静的サイトジェネレーター(高速・SEOに強い)
- **`src/content/posts/`** — 公開を承認した記事だけを置くMarkdown領域。既存4記事はそのまま維持
- **`data/topics.json`** — 記事化するキーワードのキュー
- **`scripts/generate-post.mjs`** — キューから1件取り出し、リポジトリ外に確認待ちの下書きを生成
- **`scripts/private-drafts.mjs`** — 非共有の下書き保存・重複生成防止・排他制御
- **`tests/`** — 生成・バリデーションロジックの単体テストスイート
- **`.github/workflows/generate-post.yml`** — 同じ毎日21時JSTの時刻にオフラインテストとビルドだけを実行
- **`.github/workflows/ci.yml`** — テストとビルドの自動検証CI

## ローカルでの動作確認

```bash
npm ci
npm test          # 単体テストの実行(node:test)
npm run dev       # http://localhost:4321 で確認
npm run build     # 本番ビルド(dist/に出力)
npm run test:build-safety # 合成データを使う実ビルドの下書き漏えい検証
```

## 下書き作成と公開の境界

### 1. APIを使う前に確認すること

APIの利用・選択モデル・費用上限は別途承認が必要です。この変更を取り込む承認は、API利用や記事公開の承認ではありません。
本修正の検証では実APIを呼んでいません。モデルの利用可否と最新料金は、利用前に提供元で確認してください。
APIキーはチャットやコードに書かず、安全なローカル環境変数として設定します。
GitHub Secretsを追加するだけでは、このワークフローは生成を再開しません。

### 2. 承認済みの非共有ローカル環境で下書きを作る

次の環境変数を設定します。`.env` は自動読み込みされません。

- `ANTHROPIC_API_KEY`: 承認済みの認証情報。値を表示・記録しない
- `GENERATE_POST_APPROVED=1`: API利用・費用を確認した後だけ設定
- `PRIVATE_DRAFTS_DIR`: リポジトリ外の絶対パス。親ディレクトリは事前に存在する必要があります
- `GENERATE_POST_MODEL`: 任意。未指定時は既存の `claude-haiku-4-5-20251001`

保存先には、Git管理・クラウド同期・共有・Web配信の対象でない場所を選びます。
Linux/macOSではディレクトリ0700・ファイル0600を使用します。Windowsでは事前にOSのACLで自分以外のアクセスを制限してください。
保存先がリポジトリ内、シンボリックリンク、他の人が読み書き可能な場合は停止します。

```bash
npm run generate:post
```

このコマンドは先に `npm test` と `npm run build` を実行し、どちらかが失敗したらAPIを呼びません。
CI/GitHub Actionsでの生成は、設定が揃っていても拒否します。
1回の実行で最大1リクエストとし、SDKの自動リトライも無効です。

下書きは保存先の `<keyword-sha256>.json` に `status: needs_review`、本文の `draft: true` とともに保存されます。
本文のSHA-256も記録します。生成では `src/content/posts/` と `data/topics.json` を一切更新しません。
確認待ちのトピックは次回生成から除外されるため、完了扱いにせず二重課金も防ぎます。
API失敗・出力切り詰め・検証不合格は保存せず停止し、生の応答はログに出しません。SDKの `DEBUG=true` も拒否し、API送信先をAnthropic公式エンドポイントに固定します。

### 3. 確認してから公開する

1. 下書きの `markdown` を非共有のエディタで読み、製品・機能・価格等の主張を一次情報で照合。リンク、比較の公平性、商標、広告表示も確認
2. 修正が必要なら非共有のコピーで行い、最終原稿をもう一度確認。JSON内のハッシュを手書きで変えて確認済みにしない
3. 最終原稿を公開リポジトリに置くこと、およびWebサイトへ公開することについて明示的に承認する。公開ブランチやPRへの保存も公開にあたります
4. 承認した原稿だけを `src/content/posts/<slug>.md` に保存し、`reviewStatus: approved`、`draft: false` にする。`needs_review` のまま `draft: false` にするとビルドは失敗します
5. `npm test`、`npm run build`、`npm run test:build-safety` が成功し、差分に下書きJSON・認証情報・意図しないファイルが含まれないことを確認する
6. 承認されたコミット・公開を行い、対象の原稿が反映されたことを確認してから、そのトピックを `done: true` にする。失敗・未確認なら完了にしない

公開・原稿昇格の自動コマンドはありません。既存4記事は今回あらためて事実確認・承認したものではなく、変更前の公開対象として維持しています。
Gitignoreは事故防止の補助です。強制追加や手作業による転載まで防ぐものではありません。

### 4. 失敗からの復旧

- `.generation.lock` が残った場合は、他に実行中の処理がないことを確認してから削除。確認なしに再実行しない
- 不完全なJSONやハッシュ不一致では自動上書きしない。非共有のバックアップを作成し、人が原因を調べる
- 再生成したい場合は既存の確認待ち原稿を非共有の別ディレクトリへ退避し、追加費用を確認してから実行
- API後の保存失敗では課金済みの場合があります。自動再試行しない

## 公開・収益化に進む際の別途手続き

以下は今後の選択肢です。この修正ではマージ・公開・契約・認証情報の設定は行いません。

### 3. ドメイン取得 & ホスティング契約

1. 好きなレジストラでドメインを取得(お名前.com、Cloudflare Registrar等)
2. [Cloudflare Pages](https://pages.cloudflare.com/) または
   [Vercel](https://vercel.com/) にGitHubリポジトリを接続
   - Build command: `npm run build`
   - Output directory: `dist`
3. 独自ドメインを接続
4. `astro.config.mjs` の `site` を実際のドメインに変更してpush
   (sitemap.xmlの生成に必要)。`public/robots.txt` のSitemap URLも同時に更新

ホスティングをGit連携するとpushが公開につながる場合があります。公開前に接続先とデプロイ条件を確認してください。定期QAジョブはpushしません。

### 4. `about.astro` / `contact.astro` の仮情報を実情報に差し替える

`src/pages/about.astro` と `src/pages/contact.astro` の `TODO` コメント箇所を、
実際の運営者名・連絡先メールアドレスに書き換えてください。
AdSense審査や訪問者からの信頼性のために必須です。

### 5. Google AdSenseに申請

1. 記事が15〜20本程度たまり、独自ドメインでの運用実績が数週間できてから
   https://www.google.com/adsense/ で申請
2. 審査には運営者情報・プライバシーポリシーページが必須(既に用意済み)
3. 承認されたら発行される `ca-pub-xxxxxxxxxxxxxxxx` を
   ホスティング側の環境変数 `PUBLIC_ADSENSE_CLIENT_ID` に設定
4. 広告ユニットを作成し、そのスロットIDを `PUBLIC_ADSENSE_SLOT_ID` に設定
5. 再デプロイすると記事ページに広告が表示されるようになります
   (`src/components/AdSlot.astro` が両方の環境変数が揃うまで自動的に非表示にします)

### 6. Amazonアソシエイト(または他のASP)に申請

1. https://affiliate.amazon.co.jp/ で申請(サイトにある程度コンテンツが必要)
2. 承認後、紹介したい商品のアソシエイトリンクを取得
3. 記事内で `<AffiliateLink href="..." label="..." />` コンポーネントを使って
   リンクを追加(`href` を渡さないと「リンク準備中」と表示され、空リンクを
   公開してしまうミスを防げます)

### 7. 運用を回す

- キーワードは `data/topics.json` で管理し、承認済みのローカル環境で下書きを作成します
- すべての新規原稿は公開前に人が確認し、公開を明示的に承認します
- 収益が発生したら、個人事業として確定申告が必要になる場合があります。
  国税庁のサイトや税理士に相談してください。

## 注意事項

- AIが生成した記事に、実在しない製品名や不確かな数値が紛れ込む可能性があります。
  公開前の事実確認と公開承認を必須にします。
- 「完全放置で即収益」にはならず、AdSense審査やSEOでの検索流入が育つまで
  数週間〜数か月は収益がほぼゼロの助走期間があります。
